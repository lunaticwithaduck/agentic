Its purpose: prevent silent breakage when you change one bench file without updating its dependents.

## Coupling Map

> **If you change X, you must also check Y.**

### metrics.sh JSON schema (`suites.<name>.*` fields)
Dependents that parse these keys:
- `bench/lib/report.py` — `render_run()`, `suite_notes()` — reads per-suite fields by name
- `bench/suites/04-task-quality.sh` — reads `infra_wins`, `vanilla_wins`, `ties`, `infra_win_rate`, `avg_delta`, `avg_with_score`, `avg_without_score`, `pass`, `tasks[]`
- `bench/results/changelog.md` — generated by metrics.sh; schema change breaks history rendering in report.py

**Required top-level keys** (report.py depends on all of these):
```
timestamp, git_sha, overall.{score, passed, failed, duration_ms}, suites.<name>.{passed, failed, score, duration_ms}
```

**Suite 02 extra keys** (report.py `suite_notes`): `precision`, `recall`, `f1`
**Suite 03 extra keys** (report.py `suite_notes`): `false_positive_rate`, `false_negative_rate`, `block_corpus_size`, `allow_corpus_size`
**Suite 04 extra keys** (report.py `suite_notes`): `infra_wins`, `vanilla_wins`, `ties`, `infra_win_rate`, `avg_delta`
**Suite 05 extra keys** (report.py `suite_notes`): `total_skills`, `duplication_rate`, `noisy_skill_count`

### compare.py output JSON
Suite 04 (`04-task-quality.sh`) parses these fields from compare.py `--json` output:
```
infra_wins, vanilla_wins, ties, infra_win_rate, avg_delta, avg_with_score, avg_without_score, pass, tasks[].{task_id, title, with_score, without_score, delta, winner}
```
If you rename any of these in compare.py, update the corresponding `python3 -c` expressions in `04-task-quality.sh`.

### compare.py cache key naming
`bench/e2e/cleanup.sh` uses these glob patterns to delete caches:
```
with-infra*.txt      # matches with-infra.txt and with-infra-sub.txt
without-infra*.txt
judgement*.json
summary-*.json
```
If you add a new cache variant in compare.py, add a matching glob to cleanup.sh.

### Suite file names (`bench/suites/NN-name.sh`)
`bench/lib/report.py` has a hardcoded `SUITE_LABELS` dict:
```python
SUITE_LABELS = {
    "01-infrastructure":  "01 · Infrastructure  ",
    "02-skill-detection": "02 · Skill Detection ",
    "03-hook-security":   "03 · Hook Security   ",
    "04-task-quality":    "04 · Task Quality    ",
    "05-keyword-overlap": "05 · Keyword Overlap ",
}
```
Any suite not in this dict renders with its raw filename. Add a label when you add a suite.

### `.claude/skills/*.md` (skill library)
- `bench/e2e/tasks.json` — `expected_skills` arrays reference skill names. If you delete a skill, search tasks.json for it and remove references.
- `bench/suites/01-infrastructure.sh` — validates that every .md has a rule in skill-rules.json and vice versa (automated, no threshold to update).
- `bench/suites/02-skill-detection.sh` — runs against `bench/fixtures/skill-detection/`. If you add a skill, consider adding fixture prompts that should/shouldn't trigger it.

### `block-secrets.sh` exit codes
`bench/suites/03-hook-security.sh` relies on the contract:
- exit 0 = command allowed
- exit 1 = command blocked (with JSON `{"decision":"block",...}` on stdout)

If you change this contract in `.claude/hooks/block-secrets.sh`, update the parsing logic in suite 03.

### Agent / command counts
`bench/suites/01-infrastructure.sh` has these hardcoded minimums:
```bash
agent_count  >= 3   # line ~147
cmd_count    >= 5   # line ~158
```
If you add/remove agents or commands, the test still passes as long as you stay above the floor. If you drop below, either add back or lower the threshold deliberately (with a comment).

### `bench/README.md` suites table
Manually maintained. Update when you add/remove/rename a suite.

## Operation Checklists

### Adding a new suite `NN-name.sh`

- [ ] Create `bench/suites/NN-name.sh` — source by run.sh automatically (no registration needed)
- [ ] Add entry to `SUITE_LABELS` in `bench/lib/report.py`
- [ ] Add a `suite_notes()` case in `bench/lib/report.py` if the suite emits extra metrics
- [ ] Update `bench/README.md` suites table
- [ ] Emit `SUITE_JSON` at the bottom of the suite file (required for metrics_record_suite)
- [ ] Run `bash bench/run.sh` to verify the new suite integrates cleanly

### Removing a suite

- [ ] Delete `bench/suites/NN-name.sh`
- [ ] Remove entry from `SUITE_LABELS` in `bench/lib/report.py`
- [ ] Remove `suite_notes()` case in `bench/lib/report.py`
- [ ] Update `bench/README.md`

### Adding/removing a skill

- [ ] If removing: `grep` tasks.json for the skill name in `expected_skills` and remove it
- [ ] Run `bash bench/run.sh --suite=01` to verify coverage checks pass
- [ ] If the skill had fixture prompts in `bench/fixtures/skill-detection/`, clean them up

### Changing compare.py `--json` output schema

- [ ] Update field accesses in `bench/suites/04-task-quality.sh`
- [ ] Update `suite_notes("04-task-quality")` in `bench/lib/report.py` if display fields change
- [ ] Update `SUITE_JSON` emit at the bottom of `04-task-quality.sh`

### Changing metrics.sh JSON schema

- [ ] Update `render_run()` in `bench/lib/report.py`
- [ ] Update `suite_notes()` in `bench/lib/report.py` for any affected suite
- [ ] Consider if historical `.json` files in `bench/results/metrics/` need migration

### Changing compare.py cache key names

- [ ] Update glob patterns in `bench/e2e/cleanup.sh`

### Changing block-secrets.sh exit/output contract

- [ ] Update parsing logic in `bench/suites/03-hook-security.sh`

## Key Gotchas

1. **Suite 04 skips inside Claude Code sessions** — `CLAUDECODE` env var is set inside any active Claude Code session. `04-task-quality.sh` detects this and returns early with a skip message. To actually run suite 04, use a real terminal.

2. **Suites are `source`d, not exec'd** — They run in the same shell as `run.sh`. Variables like `SUITE_PASSED`, `SUITE_FAILED`, `SUITE_JSON` are shared. Don't `exit` from a suite (use `return 0`).

3. **compare.py strips `CLAUDECODE` from subprocess env** — Without this, nested `claude -p` calls fail. If you see "Claude Code cannot be launched inside another Claude Code session", this guard is missing.

4. **Cache keys for compare.py**: subprocess mode uses `-sub` suffix (`with-infra-sub.txt`); api mode uses no suffix. Mixing modes reuses caches incorrectly — pass `--no-cache` if switching modes mid-session.

5. **report.py alignment** — ANSI escape codes inflate Python's `len()`. Column padding uses raw string width computed separately. Don't naively use f-string format width with colored strings.

6. **changelog entries are prepended** — `metrics.sh` inserts new entries after the first `---` marker. Editing the header block can break this insertion point.
