## Idea

Track what was built and what was benchmarked with a lightweight internal version
record — not semantic versioning, just a machine-readable artifact that ties a
ship output to the source state that produced it and the bench results that
validated it.

## What to Track

**Build manifest** (`ship/.build-manifest.json`):
```json
{
  "built_at": "2026-03-12T18:30:00Z",
  "git_sha": "abc1234",
  "git_branch": "develop",
  "platforms": ["claude-code", "cursor"],
  "file_counts": { "claude-code": 37, "cursor": 25 }
}
```
Generated by `buildScripts/build.sh` at the end of every run. Lives in `ship/` and gets
committed alongside the distribution artifacts. Lets anyone looking at `ship/` know
exactly what source state produced it without reading git log.

**Bench result linkage** — metrics JSON already captures `git_sha`. The gap is
going the other direction: given a ship build, which bench run validated it?
The manifest could include a `bench_run` field pointing to the latest metrics
timestamp at build time. `build.sh` reads the latest file in
`bench/results/metrics/` and records its timestamp.

## Why It's Useful

- Audit trail: "when did we ship this version and what was the bench score?"
- CI integration: a future CI step can verify the manifest exists and the linked bench
  run passes before accepting a build
- Debugging: when a user reports an issue, they can share the manifest to identify
  exactly which source state they're running
- Internal tracking without full semver overhead — a git sha is precise but opaque;
  the manifest makes the build provenance readable at a glance

## What This Is Not

This is not user-facing versioning (no v1.0.0, no changelog for end-users, no release
artifacts). That's a separate idea. This is purely internal — for developers working
on agentic itself.

## Implementation

Minimal: 10-15 lines added to `build.sh` at the end. No external dependencies.
The hardest part is deciding whether to commit the manifest or .gitignore it.
Committing is correct — the manifest is part of the ship artifact.

## Potential Integration with Bench

`bench/run.sh` could optionally accept `--tag=<build-sha>` and write it into the
metrics JSON alongside the git sha. This would create a direct link from a bench run
to the ship build it was meant to validate.
